# 业务角色任务卡

本页可打印或直接分配给演示参与者。每张任务卡从一个真实业务角色出发，明确需要点击的位置、输入的问题和完成标准。

## 任务卡 1：经营负责人

**目标：** 在两分钟内判断当前经营规模、重点区域和最需要关注的问题。

1. 打开“仪表盘”，先阅读“指标口径与数据范围”。
2. 在区域筛选中选择当前场景的重点区域，例如电商场景的“华东”。
3. 记录销售额、数量、客单价和毛利率的变化，再点击“清空筛选”。
4. 打开“智能查询”，运行 `本月各区域GMV / 交易额排名如何？`。

**完成标准：** 能说明数据截至日期、至少一个指标公式、一个区域对比发现和后续核查方向。

## 任务卡 2：分析师

**目标：** 将一次经营问题转换为可审计的查询、图表和可导出明细。

1. 在“智能查询”输入 `本月各商品品类GMV / 交易额排名如何？`。
2. 检查结果摘要、只读 SQL、图表和表格是否一致。
3. 点击“导出 CSV”，命名为 `经营分析-品类排行.csv`。
4. 再运行 `最近30天GMV / 交易额趋势如何？`，比较排行与趋势视角。

**完成标准：** 能解释 SQL 只读展示的目的，并交付一个 CSV 结果文件。

## 任务卡 3：运营负责人

**目标：** 把异常线索转化为可负责、可复盘的行动。

1. 打开“异常归因”，选择一条需核查的变化线索。
2. 进入“行动中心”，在建议草案中点击“载入草案”。
3. 填写负责人“王晨”、截止日期、目标指标和数据证据。
4. 创建待确认行动，随后标记为执行中。
5. 填写“已核查商品组合、重点订单与履约节奏；下周复查复购和毛利变化。”并完成复盘。

**完成标准：** 行动的状态经历“待确认 -> 执行中 -> 已复盘”，且保留负责人、证据和复盘结论。

## 任务卡 4：汇报专员

**目标：** 生成一份包含数据概览、异常和预测的可编辑月报。

1. 打开“报告生成”，选择“月报”。
2. 保留销售概览、区域分析、产品排行、异常指标和趋势预测五个模块。
3. 点击“生成报告”，检查标题、数据范围和模块内容。
4. 点击“导出 Markdown”，作为经营例会材料底稿。

**完成标准：** 能说明报告内容由哪些模块组成，并给出 Markdown 导出物。

## 任务卡 5：数据管理员

**目标：** 在不影响当前数据的前提下，检查并导入新数据，同时核验数据批次。

1. 打开“场景库”，选择“电商经营”。
2. 使用同目录的 [自有数据导入示例_电商.csv](scenarios/自有数据导入示例_电商.csv)。
3. 点击“检查数据质量”，确认有效记录、日期范围、维度覆盖和金额/收益汇总。
4. 说明预检不会写入数据；确认无误后点击“确认导入并替换当前数据”。
5. 在“数据版本追溯”确认出现来源为“自有 CSV”的新批次，并核对记录数、日期范围和 SHA-256 指纹。

**完成标准：** 能区分预检与正式导入，并说明批次记录不保存原始 CSV 内容。

## 任务卡 6：AI 管理员

**目标：** 理解可选 AI 配置的最小输入与安全边界。

1. 打开“系统配置”，确认默认服务类型为“DeepSeek API”。
2. 说明 DeepSeek 仅需要用户填写 API Key，Base URL、模型和超时由系统给出默认值。
3. 说明“连接测试”只验证配置可用性，保存后 Key 只会以脱敏状态展示。
4. 切换到“其他 OpenAI 兼容服务”，说明此时需要填写完整服务字段；不要在投屏环境录入真实 Key。

**完成标准：** 能解释 AI 不可用时的本地规则回退，以及模型不会直接获得数据库执行权限。
