# 功能扩展与优化路线图

## 1. 目标

下一阶段从“可演示的智能 BI 原型”向“可持续使用的决策辅助工作台”推进。优先原则是：先保证数据可信与结论可解释，再扩大 AI 能力和行业覆盖；每一项功能均保留可验证的输入、证据和安全边界。

## 2. 优先级总览

| 优先级 | 方向 | 用户价值 | 当前状态 |
| --- | --- | --- | --- |
| P0 | 数据导入前质量预检 | 导入前知道数据是否适合趋势、对比和预测，避免误替换 | **本轮已实现**。 |
| P1 | 指标口径与语义层 | 让业务人员统一理解“收入、订单、毛利”等指标 | 待实施。 |
| P1 | 数据源连接与增量同步 | 从手工 CSV 走向受控数据库/文件夹连接 | 待实施。 |
| P1 | 决策行动闭环 | 将“建议”转化为负责人、截止日期和复盘结果 | 待实施。 |
| P2 | AI 评测与问答可信度 | 用样题集衡量 AI 意图、SQL 和叙述质量 | 待实施。 |
| P2 | 权限、审计与协作 | 支持多人在真实业务环境中安全使用 | 待实施。 |
| P3 | 生产可观测性与规模化 | 支撑长期稳定运行和更大数据量 | 待实施。 |

## 3. 本轮已执行：数据质量预检

### 问题

原有导入流程会在点击后直接替换当前数据集。虽然字段校验严格，但用户无法事先知道数据覆盖范围是否足以支撑区域对比、异常归因和趋势预测。

### 交付

- 新增 `POST /api/scenarios/import/preview`，复用与正式导入相同的严格 CSV 校验，但不写数据库、不清空历史、不改变场景状态。
- 返回有效记录数、日期范围、覆盖月份、组织/分类/对象维度数、金额与收益汇总、质量提醒。
- 场景库新增“检查数据质量”按钮；只有预检成功后才可“确认导入并替换当前数据”。
- 对少于 30 行、少于 3 个月、维度单一或收益口径异常的数据明确提示分析限制。

### 验收标准

1. 不合规 CSV 在预检阶段直接拒绝，错误与正式导入一致。
2. 预检不会修改 `sales_order`、查询历史或当前场景状态。
3. 用户在页面看到预检摘要与提醒后，才能确认替换数据。
4. 后端集成测试和前端 API 客户端测试覆盖该流程。

**验证结果（2026-08-01）：** 前端 Node 测试 16 项通过；后端容器场景集成测试 4 项通过；经 `8080` 地址实测，预检前后当前数据均为 1080 条。

## 4. 下一阶段建议

### 4.1 P1：指标口径与语义层

**要解决的问题：** 相同“收入”在不同部门可能有不同计算口径，单靠字段名难以治理。

**建议能力：** 指标版本、负责人、计算公式、适用场景、更新时间、血缘说明和前端指标提示；查询、报告与 AI 提示词均读取这一份定义。

**验收：** 选择任意指标可查看口径；口径变更后历史报告保留版本；不允许 AI 自行创造未注册指标。

### 4.2 P1：受控数据源连接与增量同步

**要解决的问题：** CSV 适合演示，但真实业务需要定期更新。

**建议能力：** CSV 批次管理、Excel/数据库只读连接器、字段映射向导、预检报告、数据快照与增量同步日志。

**验收：** 每次导入有批次号、行数、错误行和回滚入口；连接器只授予最小只读权限；同步失败不覆盖上一份有效数据。

### 4.3 P1：决策行动闭环

**要解决的问题：** 当前系统能提出“下一步怎么办”，但无法追踪是否执行与是否有效。

**建议能力：** 将建议转成行动项，设置负责人、截止时间、目标指标、复盘结论和关联查询；仪表盘显示行动完成率与效果变化。

**验收：** 每条行动可追溯到数据证据与原始问题；行动关闭前必须记录结果；不把系统建议自动当作已批准行动。

### 4.4 P2：AI 评测与可信度管理

**要解决的问题：** 外部模型可能更换，单次“能回答”不足以证明持续可靠。

**建议能力：** 场景化金标准问题集、意图匹配率、SQL 安全拦截率、结果一致性、回答引用覆盖率与模型版本记录。

**验收：** 每次更新模型或提示词自动跑回归；低于阈值时仅允许本地模式或人工复核模式。

### 4.5 P2：权限、审计与协作

**建议能力：** SSO/RBAC、行列级权限、导出审批、查询审计、共享报告和评论。

**验收：** 用户只能访问被授权数据；导出、AI 配置、数据连接和指标编辑均有审计记录。

### 4.6 P3：生产可观测性与性能

**建议能力：** 结构化日志、指标监控、慢查询、异步报告队列、缓存、备份恢复演练和容量告警。

**验收：** 能定位单次请求的 `request_id`；大报告不阻塞 Web 请求；恢复演练可从备份得到可用实例。

## 5. 技术债与体验优化清单

- 将轻量图表逐步替换为支持缩放、导出和无障碍描述的图表组件。
- 为所有前端关键页面补充组件测试和真实浏览器交互测试。
- 增加数据时间口径选择，避免“本月”依赖样例数据的最新日期而让用户误解。
- 报告中显示数据截止日期、指标版本、场景/导入批次和限制提示。
- 在手机端采用折叠式导航和可横向滚动的宽表，持续通过真实移动设备或浏览器模拟验收。

## 6. 实施顺序

推荐顺序为：数据预检（已完成） -> 指标语义层 -> 数据源批次与同步 -> 决策行动闭环 -> AI 评测 -> 权限审计 -> 生产可观测性。这样可以避免在数据口径不稳定时过早叠加复杂 AI 或协作功能。
