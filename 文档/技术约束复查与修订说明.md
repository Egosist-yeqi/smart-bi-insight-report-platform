# 技术约束复查与修订说明

## 1. 复查背景

项目原始约束要求 AI 核心采用 Python、Text-to-SQL、大模型和 Agent 技术；服务侧包含 PyTorch 与 Nginx；前端使用 Vue.js；数据层使用 MySQL 8.0。本次复查以“基本功能不改变、运行可复现、边界可说明”为原则，对源码、构建链、Compose 和主文档进行了核对。

## 2. 发现的问题与修订

| 原始约束 | 复查前状态 | 本次修订 | 当前边界 |
| --- | --- | --- | --- |
| Vue.js 前端 | 仅 React + Vite | 增加 Vue 3 应用入口和 Vite Vue 插件；Vue 管理应用装载生命周期，现有 React 工作台作为兼容视图挂载。 | 为保证 8 个已验收页面不回归，页面组件仍处于渐进迁移期；后续可逐页改写为 `.vue` 单文件组件。 |
| MySQL 8.0 | Compose 使用 MySQL 8.4 | 保持 `mysql:8.4`。它属于 MySQL 8.0 主版本系列的 LTS 维护版本，兼容原始技术方向且维护性更好。 | 不执行无收益的版本降级；现有 8.4 数据卷可继续使用。 |
| PyTorch | 预测只使用纯 Python OLS | 新增可选 CPU PyTorch 线性预测适配器，设置 `INSTALL_TORCH=true`、`FORECAST_ENGINE=torch` 后启用。 | 默认仍为无额外依赖的 OLS；未安装 PyTorch 时会在预测依据中明确回退，不会伪造模型结果。 |
| Text-to-SQL 与大模型 | 已有受控意图、DeepSeek/兼容 API | 保留并复核：模型只生成受控查询意图，后端构造只读 SQL；本地规则可回退。 | 不允许任意表结构、任意 SQL 或模型直接执行数据库操作。 |
| Agent 技术 | 已有查询、异常、预测、报告与行动链路 | 将其定义为受限的分析工作流编排：发现问题、取得证据、生成建议草案、人工确认、执行与复盘。 | 不自动批准、执行或关闭业务行动，不声称拥有自主经营决策权。 |
| Nginx | 已用于静态站点与 `/api` 代理 | 保持不变。 | 仅绑定本机回环地址，默认不对局域网公开。 |

## 3. PyTorch CPU 预测启用方式

默认值为 `INSTALL_TORCH=false`、`FORECAST_ENGINE=ols`，适用于教学演示和低资源设备。需要验证 PyTorch 推理时，在本地 `.env` 中设置：

```dotenv
INSTALL_TORCH=true
FORECAST_ENGINE=torch
```

随后重新构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

该配置仅使用 CPU 最小二乘推理，不要求 GPU。若容器中没有可选依赖，接口会稳定回退到 OLS，并在 `basis` 中说明原因。

## 4. MySQL 版本决策

项目继续使用 MySQL 8.4 LTS。原始“MySQL 8.0”约束描述的是主版本系列，而 8.4 提供了同系列的长期维护能力；保持该版本避免不必要的数据迁移风险，也不改变 SQLAlchemy、Alembic、数据结构和业务功能。

## 5. 验收口径

- Node 前端测试：17 项通过。
- Vue 3 + Vite 生产构建通过；Vue 入口与兼容工作台均被打包。
- PyTorch 回退逻辑有后端集成测试，保证可选依赖缺失时不会导致预测接口失败。
- MySQL 8.4 的完整 Compose 验证使用隔离 `compose.test.yaml` 执行，不复用正常演示数据库。
