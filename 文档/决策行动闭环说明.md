# 决策行动闭环说明

## 1. 解决的问题

异常、预测和自然语言查询可以指出需要关注的方向，但“系统提出建议”不等于“业务已经决定并执行”。行动中心把这两者分开：分析结论先作为建议草案，业务人员确认后才创建行动记录，并在执行完成后留下复盘结论。

## 2. 使用流程

1. 在“异常归因”“趋势预测”或“智能查询”中获得数据证据。
2. 打开“行动中心”，选择与当前行业场景匹配的建议草案，或直接创建自定义行动。
3. 填写行动内容、负责人、截止日期、优先级、目标指标和数据证据，点击“创建待确认行动”。
4. 负责人确认开始执行后，点击“标记为执行中”。
5. 执行结束时填写复盘结论，再点击“完成并复盘”。未填写复盘结论时服务端会拒绝关闭操作。

## 3. 状态和边界

| 状态 | 含义 | 可见操作 |
| --- | --- | --- |
| 待确认 | 已记录但尚未由业务方开始执行 | 标记为执行中，补充证据。 |
| 执行中 | 已由人工确认并在推进 | 填写复盘并关闭。 |
| 已复盘 | 已记录实际结果和后续安排 | 查看证据与复盘结论。 |

- 行动建议来自当前行业场景的通用核查方向，不会被系统自动批准、自动执行或自动关闭。
- 当前为本地单用户原型，负责人是文本字段，不代表权限或真实消息通知。
- 行动项会随数据库保留；切换行业场景或导入 CSV 不会删除已有行动，避免丢失业务复盘记录。
- 未提供登录和审批流，因此不能将行动清单作为企业级授权或审计依据。

## 4. 接口

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/actions` | GET | 返回行动列表，以及待确认、执行中、已复盘、逾期汇总。 |
| `/api/actions` | POST | 创建待确认行动。 |
| `/api/actions/{action_id}` | PATCH | 更新状态、负责人、截止日、目标、证据或复盘结论。 |

关闭行动时请同时提交 `status: "completed"` 和非空 `review_notes`；否则接口返回 `ACTION_REVIEW_REQUIRED`。
