# 部署与运维手册

## 1. 使用对象与前置条件

适用于 Windows 10/11 本地演示、答辩和开发。需要 Docker Desktop 已安装并等待 Engine 运行；只有在执行前端本地测试或构建时才需要 Node.js LTS。

## 2. 一键启动与访问

1. 双击项目根目录 `启动智能BI系统.cmd`。
2. 启动器会检查 Docker Desktop；首次启动会构建镜像、初始化环境和数据库，随后自动打开浏览器。
3. 访问 `http://localhost:8080`，接口文档为 `http://localhost:8080/api/docs`。

日常启动也可运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

成功标志是健康接口返回应用和数据库均为 `up`：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
```

## 3. 日常操作

| 目标 | 操作 |
| --- | --- |
| 停止系统但保留数据 | 双击 `停止智能BI系统.cmd`，或运行 `scripts/stop.ps1`。 |
| 重置演示数据 | 仅在明确需要时运行 `scripts/reset.ps1 -ConfirmReset`；该操作会删除当前项目的 MySQL 数据卷。 |
| 查看服务状态 | `docker compose ps`。 |
| 查看后端日志 | `docker compose logs backend`。 |
| 查看数据库/前端日志 | `docker compose logs mysql`、`docker compose logs frontend`。 |
| 完整测试 | 运行 `scripts/test.ps1`，使用隔离测试环境。 |

## 4. AI 服务配置

在“系统配置”页面选择模型类型：

- **DeepSeek API（默认）**：只填写 API Key。系统自动使用 DeepSeek 预设地址、模型和超时。
- **其他 OpenAI 兼容服务**：填写服务名称、Base URL、模型名、API Key、超时；仅可信内部服务场景可主动允许私网访问。

先点击“连接测试”，确认返回有效结构后再保存。API Key 不应写入文档、截图、CSV、代码仓库或聊天内容；删除配置会回到本地规则模式。

## 5. 常见故障处理

| 现象 | 建议处理 |
| --- | --- |
| 浏览器提示连接被拒绝 | 确认启动器窗口没有报错，执行 `docker compose ps`；等待服务健康后刷新。 |
| Docker Desktop 未就绪 | 打开 Docker Desktop，等待 Engine running，再运行启动器。 |
| 8080 被占用 | 检查占用该端口的程序，或停止旧的本项目容器后重试。 |
| 数据库状态异常 | 执行 `docker compose logs mysql` 与 `docker compose logs backend`，不要直接删除未知 Docker 卷。 |
| AI 连接测试失败 | 检查 Key、模型名称、Base URL 和网络策略；删除配置后可继续使用本地模式。 |
| 导入失败 | 检查 CSV 是否使用 [字段模板](demo/scenarios/字段模板.csv) 的 11 个字段、日期与数值格式。 |

## 6. 安全约束

- `.env` 包含数据库密码和应用加密密钥，不能提交或分享。
- 端口仅监听本机回环地址，不要自行改为公网暴露。
- 正常停止不会删除数据；重置前应确认自己操作的是本项目而非其他 Docker 服务。
- 数据库、API Key 与真实业务数据应使用受控备份和最小权限管理。
