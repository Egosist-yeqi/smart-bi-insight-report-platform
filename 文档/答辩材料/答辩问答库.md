# 答辩问答库

## 产品与业务

### 1. 这和普通 BI 仪表盘有什么区别？

普通 BI 主要回答“数是多少”。本系统在图表之外提供自然语言查询、受控 SQL、异常归因线索、行动建议、预测和报告，把信息展示延伸为可追溯的决策辅助流程。

### 2. 为什么要做行业场景库？

同一个“销售额”在医院、银行和互联网公司中的业务含义不同。场景库同步替换数据、术语、模板问题、根因核查项和建议动作，让演示与自有数据导入有明确边界，而不是泛泛地说“任何行业都能用”。

### 3. 系统给出的“原因”可靠吗？

系统返回的是基于维度拆解的证据和业务核查方向，不把相关性说成因果性。页面和文档均提示用户结合业务事实确认，属于辅助决策而不是自动决策。

## 技术实现

### 4. 为什么选 React、FastAPI 和 MySQL？

React 适合构建交互式工作台，FastAPI 便于以 Pydantic 模型约束 API 和自动生成接口文档，MySQL 适合保存结构化业务明细。三者使用 Docker Compose 组合，便于本地复现和展示。

### 5. Text-to-SQL 是不是直接让大模型生成并执行 SQL？

不是。默认模式使用本地受控解析；启用 AI 后，AI 只返回意图或叙述增强，后端仍以固定指标、维度和时间范围构建参数化只读 SQL，并拦截写入、多语句和高风险关键词。

### 6. DeepSeek 怎么配置？

用户在系统配置页选择 DeepSeek API 后只需填入自己的 Key，再连接测试和保存。选择其他 OpenAI 兼容服务时才需要填写 Base URL、模型和超时等字段。

### 7. API Key 如何保护？

Key 不返回浏览器；服务端用 Fernet 加密保存，界面只显示脱敏提示。文档、测试和截图不包含真实 Key，删除配置可立即回退本地模式。

### 8. 为什么自有数据必须用 11 个字段？

这是原型阶段的受控数据契约。它确保金额、数量、时间、组织、对象、分类与收益都有明确含义，系统才能可靠提供查询、趋势、异常和报告。未知字段不会被模型猜测或执行。

## 算法与质量

### 9. 预测使用了什么算法？

当前是基于历史月度数据的轻量趋势预测，适合展示工作流而非做经营承诺。预测结果会标注为参考，后续可替换为经业务验证的时间序列模型。

### 10. 异常如何判断？

系统对完整月度数据做变化检测，再通过区域、产品、类别和对象类型做贡献拆解。输出包括数据证据与核查建议，不以单一阈值替代业务判断。

### 11. 如何证明系统不是只做了界面？

可现场打开 API Docs、查看只读 SQL 和查询结果、运行场景切换与 CSV 导入、展示 Docker 服务状态，并说明后端、前端和浏览器自动化测试记录。

### 12. 自动化测试包含什么？

完整回归包含后端 Pytest、前端 Node 单测、Vite/Nginx 生产构建和 Playwright。浏览器测试覆盖查询、报告、配置、异常、预测、桌面和移动视口，并使用独立 Docker 测试卷。

## 项目管理与展望

### 13. Codex 在项目中的作用是什么？

Codex 协助完成代码实现、调试、测试、文档整理和迭代，但项目需求、业务口径、运行验证和最终交付由项目负责人确认。成果以仓库、Docker 系统和测试证据为准。

### 14. 三周内如何安排工作？

第一周完成需求、数据模型、架构与基础工程；第二周实现查询、分析、报告和场景工作流；第三周补齐 AI 接入、安全、测试、启动器、文档与答辩材料。

### 15. 下一步最优先做什么？

优先接入受控的真实数据源和身份权限，再建立指标口径管理、查询审计与模型评测。只有这些基础治理到位，才能谨慎扩展到生产环境。
