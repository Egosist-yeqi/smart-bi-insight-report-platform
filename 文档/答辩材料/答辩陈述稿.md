# 答辩陈述稿

## 开场（约 40 秒）

各位老师好，我的项目是“智能 BI 数据洞察与报告生成平台”。它面向企业经营分析场景，解决业务人员会看报表、但不一定会写 SQL，也难以把数字快速转化为决策动作的问题。我的目标不是做一个只展示 KPI 的页面，而是形成“发生了什么、为什么发生、接下来怎么办、未来可能怎样”的分析闭环。

## 需求与方案（约 60 秒）

系统支持自然语言查询、仪表盘、报告生成、异常归因、趋势预测和场景化数据导入。为了让不同领域可以直接演示，我设计了电商、医院、银行、制造业和互联网公司五套场景。每个场景都会同时切换业务术语、数据、模板问题、核查项和行动建议，而不是只把同一份销售数据换个名字。

技术上，前端使用 React 和 Vite，Nginx 负责静态资源与 API 代理，FastAPI 承担查询、报告、异常、预测与配置接口，MySQL 保存业务明细和系统配置。系统通过 Docker Compose 一键运行。

## 核心流程与安全（约 75 秒）

用户提交问题后，系统先识别指标、时间和维度，再生成受控的只读 SQL。结果会返回 SQL、表格、推荐图表和文字摘要，用户可以核对结论的依据。默认本地规则模式无需 API Key；如果配置了 DeepSeek 或其他 OpenAI 兼容服务，AI 只用于意图理解和报告叙述增强，返回内容仍需经过服务端校验。

安全上，系统拒绝写入和多语句 SQL，Key 使用加密存储并只展示脱敏信息；前端和数据库端口仅对本机开放。导入数据也采用 11 个标准字段，保证系统只在明确的数据边界内分析。

## 现场演示（约 3 分钟）

现在我先进入场景库，以电商经营为例加载演示数据。这里的模板问题按照四个决策阶段组织。先运行“本月各区域 GMV/交易额排名如何”，系统返回查询摘要、只读 SQL、图表和结果表。

接着运行“为什么本月 GMV/交易额出现变化”。系统给出可验证的数据变化和需要进一步核查的商品组合、重点用户和履约节奏。这里我要强调，系统不会把建议包装成确定的因果结论，而是明确把它作为业务核查方向。

随后进入报告生成页，选择月报和需要的模块，生成后可以预览并导出 Markdown。最后展示异常归因和趋势预测页面，说明预测基于历史数据，仅用于辅助判断。若需要用户自有模型，可以在系统配置中选择 DeepSeek，只输入 Key 后先连接测试；删除配置后系统立即回到本地规则模式。

## 测试与收尾（约 70 秒）

项目不仅有页面。完整回归记录包含 135 项后端测试、15 项前端测试和 8 项浏览器端到端测试，测试环境与日常演示环境使用独立 Docker 项目和数据卷。仓库还提供一键启动器、演示问题、演示检查单、部署手册、答辩材料和供 AI 协作的项目上下文。

总结来说，本项目完成了一个可运行、可解释、可切换行业场景并可接入自有 AI 的智能 BI 原型。后续我会继续扩展真实数据源、权限体系、指标治理和模型评测。我的陈述完毕，谢谢各位老师。
