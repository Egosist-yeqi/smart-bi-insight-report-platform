# 答辩 PPT 大纲

建议总时长 7 至 8 分钟，PPT 保持简洁，用系统现场操作承接关键页面。

## 第 1 页：封面

- 项目名称：智能 BI 数据洞察与报告生成平台
- 项目 11、姓名/学号/指导老师、答辩日期
- 副标题：面向多行业经营分析的自然语言决策辅助原型

## 第 2 页：问题与目标

- 业务人员依赖 SQL、报表与分析师，分析链路长。
- 传统仪表盘偏“看数”，难以直接回答“发生了什么、为什么、下一步怎么办”。
- 目标：用自然语言把查询、洞察、报告、异常和预测连接成可核对闭环。

## 第 3 页：需求与范围

- 本期：场景化明细数据、Text-to-SQL、可视化、报告、异常、预测、CSV 导入、可选 AI。
- 五个行业：电商、医院、银行、制造业、互联网公司。
- 非目标：企业级多租户、生产数仓、精确预测承诺。

## 第 4 页：核心亮点

1. **决策闭环**：按“发生了什么 - 为什么 - 接下来怎么办 - 预测与模拟”组织问题和输出。
2. **行业即插即用**：切换场景即切换术语、模板问题、根因检查项、行动建议与演示数据。
3. **可解释安全**：展示只读 SQL、结果和限制；AI 不能直接执行任意 SQL。
4. **可交付**：Docker 一键启动、测试、文档、答辩素材和 GitHub 仓库齐全。

## 第 5 页：系统架构

使用 [系统设计说明书](../系统设计说明书.md) 中的架构图：React/Vite -> Nginx -> FastAPI -> MySQL，DeepSeek 或兼容 AI 作为可选增强层。

强调：本地规则模式无需 Key 也能完整演示；AI 接入失败会回退，不影响基础工作流。

## 第 6 页：数据设计与场景库

- `sales_order` 使用 11 个标准字段承接业务明细。
- 每个行业映射自己的金额、数量、组织、分类和对象术语。
- 导入 CSV 用模板约束数据边界，防止系统对未知字段编造分析。

## 第 7 页：核心流程

展示流程：提问 -> 意图解析 -> 只读 SQL 校验 -> MySQL 查询 -> 图表/表格/结论 -> 历史与导出。

可放一张智能查询页面截图或直接切入现场操作。

## 第 8 页：现场演示

1. 场景库切换到电商或医院。
2. 运行“本月各区域经营金额排名如何？”。
3. 运行“为什么本月经营金额出现变化？”并展示根因核查线索。
4. 生成月报，展示导出。
5. 切换到预测页面，说明预测边界。

## 第 9 页：AI 接入与安全

- DeepSeek 下拉选项仅输入 Key；其他兼容服务填写完整字段。
- Key 加密保存、脱敏显示、连接测试、删除后回退本地模式。
- 端口本机绑定、可信 Host、只读 SQL、私网显式授权、请求 ID 与隔离测试。

## 第 10 页：测试与验收

- 后端 Pytest 135 项、前端单测 15 项、Playwright 8 项的完整回归记录。
- 生产构建、Docker 服务健康、Chrome 端到端流程。
- 现场展示 GitHub、启动器与文档总览。

## 第 11 页：三周开发组织

- 第 1 周：需求、数据模型、全栈与 Docker 基础。
- 第 2 周：查询、仪表盘、报告、异常和预测工作流。
- 第 3 周：AI 接入、安全、自动化测试、演示与答辩交付。

说明 Codex 用于加快实现、联调、测试和文档整理，最终以仓库、运行系统和测试证据验证成果。

## 第 12 页：总结与展望

- 已完成可启动、可演示、可导入、可解释的智能 BI 原型。
- 后续方向：RBAC、真实数据连接器、指标治理、异步任务、模型评测和生产监控。
- 致谢并进入提问。
